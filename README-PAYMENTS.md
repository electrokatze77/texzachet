# Інтеграція Platega

Платіжний модуль створює посилання Platega на сервері, приймає callback про
зміну статусу та показує покупцеві перевірений результат. Секретний ключ ніколи
не передається в браузер.

## Вимоги до сервера

- PHP 8.1 або новіший;
- розширення PHP `curl` і `json`;
- HTTPS із чинним SSL-сертифікатом;
- право PHP створювати та змінювати файли в каталозі сховища;
- Apache 2.4 або захищений приватний каталог на іншому вебсервері.

За можливості вкажіть `PAYMENT_STORAGE_DIR` як каталог поза публічним коренем
сайту. Якщо використовується стандартний каталог `storage/`, Apache закриває
до нього доступ через `.htaccess`. Для Nginx каталог потрібно додатково закрити
в конфігурації сервера.

## Налаштування

Найкращий варіант — створити змінні оточення в панелі хостингу:

```text
PLATEGA_MERCHANT_ID=<Merchant ID>
PLATEGA_SECRET=<API key>
APP_URL=https://texzachet.com
PAYMENT_STORAGE_DIR=/absolute/private/path/texzachet-payments
```

Якщо хостинг не підтримує змінні оточення:

1. Скопіюйте `config/platega.example.php` у
   `config/platega.local.php`.
2. Заповніть `merchant_id`, `secret` та `app_url`.
3. Переконайтеся, що `config/platega.local.php` не потрапив у Git. Він уже
   доданий до `.gitignore`.

Не надсилайте API-ключ у чат, JavaScript, HTML або репозиторій.

## Callback URL

У кабінеті Platega відкрийте `Настройки → Callback URLs` і вкажіть:

```text
https://texzachet.com/api/platega-webhook.php
```

Під час збереження Platega відправить порожній `POST`. Обробник відповість
`200 OK`. Для справжніх callback-ів він додатково перевіряє:

- заголовки `X-MerchantId` і `X-Secret`;
- ID транзакції;
- внутрішній ID замовлення з `payload`;
- суму та валюту;
- допустимий статус;
- коректність переходу між статусами.

Повторний callback із тим самим статусом безпечний і повертає `200 OK`.

## Файли

- `api/create-payment.php` — створює замовлення та платіжне посилання;
- `api/platega-webhook.php` — приймає callback-и;
- `api/payment-status.php` — повертає публічний статус за захищеним токеном;
- `api/bootstrap.php` — конфігурація, сховище та HTTP-клієнт;
- `assets/js/payments.js` — обробляє кнопки тарифів;
- `assets/js/payment-result.js` — перевіряє результат після повернення;
- `payment-success.html` і `payment-failed.html` — сторінки результату.

Ціни задаються тільки у `api/create-payment.php`:

| Тариф | Сума |
|---|---:|
| LITE | 2000 RUB |
| PRO | 3000 RUB |
| EXPERT | 3900 RUB |

Значення з HTML або запиту браузера не використовуються як сума платежу.
Перед створенням платежу покупець також залишає Telegram або email і явно
погоджується з користувацькою угодою та політикою конфіденційності. Контакт
зберігається тільки в серверному файлі замовлення і не повертається через
публічний API статусу.

## Перевірка перед запуском

1. Переконайтеся, що `config/platega.local.php` або змінні оточення налаштовані.
2. Відкрийте callback URL у кабінеті Platega та успішно збережіть його.
3. Натисніть кожен тариф і перевірте правильну суму на сторінці Platega.
4. Проведіть узгоджений із менеджером тестовий платіж.
5. Перевірте, що файл замовлення отримав статус `CONFIRMED`.
6. Перевірте повторну доставку callback-а: статус не повинен дублювати
   виконання замовлення.
7. Перевірте сценарії `CANCELED` та повернення `CHARGEBACKED`.

Поточний модуль підтверджує і зберігає оплату, але не надсилає автоматичне
повідомлення менеджеру. Це варто підключити окремо після успішного бойового
тесту, щоб повідомлення запускалося тільки при першому переході в
`CONFIRMED`.
